# CampfirePlatform

## 一、插件介绍
当前分支： Paper 26.3
篝火服务器配套PaperSpigot插件。

用于连接篝火后端，提供玩家账号绑定、玩家加入与退出同步、跨平台聊天同步功能。当前构建目标为 Paper 26.3，运行需要 Java 25。

玩家加入服务器、退出后重新进入，以及绑定成功后，都会向后端申请 `join`。只有 `join` 返回成功，玩家才会加入本地同步名单并允许向后端发送聊天；不影响服务器内的正常聊天。玩家退出时，只有已在同步名单里的玩家才发送 `leave`。后端传来的聊天仍向全服广播。

## 二、指令与权限

### 指令列表

`<参数>` 表示必填，`[参数]` 表示可选。

| 指令 | 用处 | 执行限制 | 权限节点 |
|---|---|---|---|
| `/bind <code>` | 使用六位数字验证码，将当前玩家的 Minecraft 账号绑定到篝火账号。绑定成功后自动重新申请 `join`。 | 仅玩家本人可执行；验证码为 `100000`～`999999`；后端连接必须就绪。 | `campfire.bind` |
| `/campfire` | 查看后端连接状态和最近一次错误，等同于 `/campfire status`。 | 玩家或控制台；需要管理权限且后端客户端已配置。 | `campfire.admin` |
| `/campfire status` | 查看后端连接状态和最近一次错误。 | 玩家或控制台；需要管理权限且后端客户端已配置。 | `campfire.admin` |
| `/campfire connect` | 重新验证并连接后端；已有连接时会断开后重新连接，也可恢复手动断开的连接。 | 玩家或控制台；需要管理权限且后端客户端已配置。 | `campfire.admin` |
| `/campfire disconnect` | 断开后端连接，并停止自动重连，直到再次执行 `connect`。 | 玩家或控制台；需要管理权限且后端客户端已配置。 | `campfire.admin` |
| `/campfire join [玩家名或UUID]` | 为指定玩家重新申请加入同步名单，等待后端返回结果。 | 后端连接必须就绪；玩家名只匹配在线玩家；省略目标时使用执行玩家自身，控制台使用配置中的身份。 | `campfire.admin` |
| `/campfire leave [玩家名或UUID]` | 移除指定玩家的本地同步资格；只有操作前已在同步名单中且连接就绪，才向后端发送 `leave`。不会删除账号绑定。 | 玩家名只匹配在线玩家；省略目标时使用执行玩家自身，控制台使用配置中的身份。 | `campfire.admin` |
| `/campfire send <消息>` | 使用执行者对应的玩家身份向后端发送聊天消息，支持包含空格的消息。 | 对应 UUID 必须已通过 `join` 加入同步名单，且后端连接就绪；不能直接指定其他玩家作为发送者。 | `campfire.admin` |

### 权限节点

| 权限节点 | 用途 | `plugin.yml` 默认值 | 默认可用对象 |
|---|---|---|---|
| `campfire.bind` | 使用 `/bind` 绑定自己的账号。 | `true` | 普通玩家默认可用，无需 OP；权限插件可显式拒绝。控制台即使拥有权限，也不能执行玩家绑定。 |
| `campfire.admin` | 使用 `/campfire` 及全部管理子指令。 | `op` | 默认 OP 可用；也可由权限插件单独授予。控制台通常拥有该权限。 |

### 使用说明

- **绑定身份**：`/bind` 自动使用执行玩家的真实 UUID，玩家只需输入验证码，不能指定其他玩家或 UUID。
- **绑定确认**：提交验证码不等于绑定成功，需等待后端结果。绑定成功后仍需等待新的 `join` 成功，才允许发送跨平台聊天。验证码不会自动重试，也不会写入插件日志。
- **控制台身份**：执行不带目标的 `join`、`leave` 或执行 `send` 时，控制台需要在 `config.yml` 的 `commands.console-player-uuid` 中配置身份；`join`、`leave` 也可显式指定目标。
- **管理权限配置**：`commands.permission` 默认是 `campfire.admin`。目前 `/campfire` 同时受 `plugin.yml` 中的 `campfire.admin` 和该配置项检查；若改为其他节点，执行者需要同时满足两个权限检查。
- **发送结果**：指令提示请求已提交，不代表后端已经接受。玩家是否允许同步，最终仍由后端校验。
